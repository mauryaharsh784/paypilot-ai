# PROJECT_PROGRESS

## Submission hardening pass (latest)
Scope: payment correctness gaps found in a read-only inspection, product images on orders, and submission material. **Not run end to end**: only syntax checks were done (no dependencies installed, no database available). Re-run `npm run typecheck`, `test:e2e`, `test:payments`, `test:acceptance` and the client build before submitting.

### Changed
- **Request-id reuse (payments.ts, paypal.ts, models.ts):** after a price change the same `create-<orderId>` `PayPal-Request-Id` was reused, so PayPal could replay the old order and amount. Orders now carry `paypalAttempt`, and the id gets an attempt suffix when it is above 0 (create and capture). Orders with attempt 0 behave exactly as before.
- **Capture verification:** `custom_id` is now required and must equal the order id. The webhook derives it from the related PayPal order id when PayPal omits it, and ignores a capture whose PayPal order id differs from the order's (`order_mismatch`).
- **Webhook idempotency (routes.ts, models.ts):** an event with no outcome yet returns 409 so PayPal retries, and a stalled event (no outcome, claimed over 2 minutes ago) is taken over. Finished duplicates still return `duplicate: true`.
- **Admin reconcile:** `POST /api/admin/orders/:id/sync` reads the order from PayPal and runs the same verification and `markPaid` (`source: 'sync'`).
- **Product images:** optional `Product.image`; included in `pub()` and the cart summary; order items store `slug`, `category`, `image`; `/orders` and `/orders/:id` fill these in for older orders at read time (no database writes).
- **Tests:** `test-payments.sh` section 8b checks that re-approval after a price change creates a new PayPal order (the mock already replays by request id).
- **Docs/CI:** `docs/SUBMISSION.md` (write-up and checklist), README and `docs/PAYPAL.md` updated, `.github/workflows/ci.yml` (typecheck and build only), demo script gets an optional cancel beat.

### Improvement pass (after the hardening pass)
- Paying removes only the ordered items from the cart (was: the whole cart).
- Stock shortfall at payment time is recorded on the capture transaction (`detail.stockShortfall`) and admins are notified.
- Unpaid checkouts expire after 24 hours (applied when the user lists their orders).
- Duplicate client cancel/error rows are suppressed (one per order, kind and status per 10 minutes); `payment-event` is rate limited (20/min).
- `/transactions` returns `amountInr`; the Transactions page shows it next to the USD amount.
- Client code-splitting (`React.lazy`): main bundle about 207 kB (was about 700 kB); charts load only on Dashboard and Admin.
- **Verified in this environment:** `npm ci`, server `tsc --noEmit`, and client `npm run build` all pass. **Not run:** the three API test suites (no MongoDB here) and anything against real PayPal.

## UI/UX improvement pass (this delivery)
Scope: front-end polish only. No routes, auth, PayPal, agent or database logic was changed. Two additive, backward-compatible server tweaks were needed (see "Server changes").

### Changed
- **Product images:** 25 per-product SVG illustrations + 5 category fallbacks in `client/public/products/`, generated by `client/scripts/generate-product-images.mjs`. New `ProductImage` component (fixed aspect ratio, `object-contain`, shimmer, 3-step fallback, lazy loading). Used on Discover, Wishlist, Price Watch, Dashboard recommendations, AI assistant cards and cart summary, Product Detail, Compare, Cart, Checkout and Order Detail.
- **Icons:** Lucide only, one stroke weight (CSS), consistent sizes. Sidebar: Dashboard, AI assistant (Sparkles), Discover, Compare, Cart, Orders, Transactions, Wishlist, Price watch, Notifications, Profile (UserCircle), Settings, Logout. Category icons now only appear as image fallbacks.
- **Design system (`index.css`):** indigo primary actions (`btn-primary`; `btn-brand` kept as alias), `btn-icon`, `card-pad`, `skeleton`, `icon-tile`, input error state, focus rings, disabled states.
- **Sidebar/mobile:** active state, aligned badges (cart, unread, compare), profile + logout block, mobile header with cart badge, drawer closes on Escape/route change and locks body scroll.
- **Dashboard:** consistent stat cards; "Paid orders" replaces the misleading "Total orders"; orders broken down by Paid / Awaiting / Cancelled / Failed; transaction chart colours by status; clearer budget progress; recommendations with images.
- **AI assistant:** avatar chat bubbles, typing indicator, error bubble, richer empty state, product cards with value-score bar and separate Strengths/Limitations, budget card, approval card, responsive input with Send button. Agent code untouched.
- **Discover:** search with icon, 2-col filters on mobile, result count, clear-filters, skeleton grid, empty/error states.
- **Cart/Checkout:** images, stepper quantity (bounded by stock/10), remove button, sticky summary, budget status, loading state on approval. PayPal flow untouched; nothing is captured without the approval checkbox + explicit PayPal approval.
- **Orders/Transactions:** table on ≥640 px, card list on mobile; status chips with icon + colour (paid green, pending amber, failed red, cancelled grey).
- **Wishlist/Price watch/Notifications:** images, status chips, icons by notification type, skeleton/empty states.
- **Profile/Settings:** validation messages, save loading state, **delete confirmation dialog** for shopping memory, environment status cards.
